# 2.13 — Avatar Upload & ErrorBoundary

## Goal
Add a user avatar upload flow on the HabitsPage (using the existing `users.avatar_url` column) and wrap the page's major sections in a reusable `ErrorBoundary` class component with fallback UI and a "Try again" button.

---

## What You Do Manually in Supabase Dashboard

### 1 — Create the `avatars` Storage Bucket (Dashboard only)
Bucket creation requires the Dashboard or the Management API. You cannot do it with SQL alone.

Steps:
1. Go to Supabase Dashboard → **Storage** → **New Bucket**
2. Name: `avatars`
3. Toggle **Public bucket** → ON
4. Leave file size limit and allowed MIME types blank (enforced client-side)
5. Click **Create Bucket**

### 2 — Run the Storage RLS Policy SQL
In Supabase Dashboard → **SQL Editor**, paste and run the SQL block provided in the "SQL to run" section below.

---

## SQL to Run in SQL Editor

```sql
-- Storage RLS: users can only INSERT/UPDATE/DELETE inside their own folder.
-- The folder name is the Clerk user ID (e.g. user_2abc.../avatar.jpg).
-- We use auth.jwt()->>'sub' because Clerk IDs are strings, not UUIDs,
-- and the Clerk-aware Supabase client injects a JWT whose 'sub' is the Clerk ID.

create policy "avatar upload own folder"
  on storage.objects for insert
  with check (
    bucket_id = 'avatars'
    and auth.role() = 'authenticated'
    and (storage.foldername(name))[1] = auth.jwt()->>'sub'
  );

create policy "avatar update own folder"
  on storage.objects for update
  using (
    bucket_id = 'avatars'
    and auth.role() = 'authenticated'
    and (storage.foldername(name))[1] = auth.jwt()->>'sub'
  );

create policy "avatar delete own folder"
  on storage.objects for delete
  using (
    bucket_id = 'avatars'
    and auth.role() = 'authenticated'
    and (storage.foldername(name))[1] = auth.jwt()->>'sub'
  );

create policy "avatar public read"
  on storage.objects for select
  using (bucket_id = 'avatars');

-- Allow users to UPDATE their own avatar_url in the users table
drop policy if exists "users update own avatar_url" on users;
create policy "users update own avatar_url" on users
  for update
  using (auth.jwt()->>'sub' = id)
  with check (auth.jwt()->>'sub' = id);
```

## Key Decisions & Assumptions

1. `users.avatar_url` already exists — no schema migration needed.
2. Clerk JWT injected by the existing `createClerkSupabaseClient(getToken)` factory — reused for storage uploads and the users UPDATE.
3. Folder path: `avatars/{clerk_user_id}/avatar.jpg`. Fixed filename so upsert replaces the previous file cleanly.
4. Public URL built via `supabase.storage.from('avatars').getPublicUrl(path)`. Bucket is public, no signed URL needed.
5. `upsert: true` ensures re-uploads replace the existing file without a 409 error.
6. Validation is client-side only: image/* MIME type check + 1 MB size check. Inline error shown beneath the input.
7. Preview via `URL.createObjectURL(file)`. Revoked on unmount or next file selection.
8. ErrorBoundary wraps: Nav (in root-layout), stats bar, habit list (in habits-page).
9. "Try again" calls `this.setState({ hasError: false })` to reset the boundary.
10. No new packages installed.

---

## Security

- Clerk JWT injected by createClerkSupabaseClient — service_role key never reaches the browser.
- RLS policies ensure users can only write to their own folder and their own users row.
- File type and size validated before upload call.
- Public URL stored in users.avatar_url, readable only by the owner per existing SELECT policy.

## ErrorBoundary Spec

Props: `{ children: ReactNode; fallbackTitle?: string }`
State: `{ hasError: boolean; error: Error | null }`

- `getDerivedStateFromError` sets hasError = true
- `componentDidCatch` logs the error
- Fallback UI: `bg-destructive/10 border border-destructive/30 rounded-lg p-6` with title, error.message, and "Try again" button

---

## AvatarUpload Component Spec

Props: `{ userId: string; db: SupabaseClient; currentUrl: string | null }`

State: `preview`, `uploading`, `error`, `avatarUrl`

Behaviour:
1. On mount: fetch `avatar_url` from `users` table using `db`. Set `avatarUrl`.
2. File input (`accept="image/*"`): validate type + size. If invalid, set `error`. If valid, set `preview` via `URL.createObjectURL`.
3. Upload button: disabled if `!preview || uploading`. On click: upload to `avatars/{userId}/avatar.jpg` with `upsert: true`, get public URL, UPDATE `users.avatar_url`, set `avatarUrl`, revoke object URL, clear `preview`.
4. Display: `<img>` showing `preview ?? avatarUrl` in a `w-16 h-16 rounded-full` circle with a camera icon overlay that opens the file input.
5. Error: inline below avatar, `text-destructive text-xs`.
